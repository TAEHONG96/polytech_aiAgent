# 구현 및 검증 기록

## 5단계 통합 테스트와 배포 안정화

2026-11-19 (KST)

별도 Compose 프로젝트에서 접수부터 분석·인수 확인까지 연결했다. PostgreSQL 회귀 41개와 Chromium 흐름·Nginx 경계 테스트를 확인했다. 컨테이너 재시작과 DB 연결 실패·복구, DB 및 SOP 원본의 새 볼륨 복원, 로컬 운영 TLS 조합을 검증했다.

- Nginx 413·로그인 429에 JSON 오류와 요청 ID를 적용했다. 일반 접근 로그에서 검색 질의 문자열을 제외했다.
- 교대 화면에서 오래된 회차 응답이 사용자가 고른 회차를 덮는 문제를 수정했다.
- 합성 질의 26개의 실제 Gemini RAG 평가에서 Recall@5 1.00, Precision@5 0.40, MRR 1.00, p95 465.77ms를 관측했다. 무관 질의 11개 중 1개에 검색 결과가 반환됐다.
- 기본 Gemini 생성 모델은 HTTP 504로 실패했다. 검증 전용 `gemini-3.5-flash-lite`에서 실제 장애 분석 도구 4개와 인수인계 도구 3개, 두 경로의 구조화 응답을 확인했다. 대상 Ubuntu 서버 검증은 남아 있다.

## 4단계 교대 인수인계

2026-11-18 (KST)

근무조·회차 등록, 티켓 배정과 작업 이력, 자동 대상 선정과 수동 선택, 원본 스냅샷과 누락 확인, AI 분석, 보고서 편집, 인계조 최종 확정, 인수조 확인을 구현했다. 확정본 이후에는 선행본을 참조하는 후속 초안을 작성한다. 기본 개발 포트는 `127.0.0.1:8080`이다. 검증은 별도 Compose 프로젝트와 `127.0.0.1:18084`에서 수행했다.

| 검증 | 결과 |
| --- | --- |
| PostgreSQL + Fake 공급자 회귀 | 31개 통과. 티켓 CRUD, SOP·검색, 장애 분석을 포함한다. 교대 검증은 자정 경계, 중첩, 자동·수동 대상, 이월, 빈 보고서, 보완 질문, 유사 기록, P1, 권한, 동시 편집, 스냅샷 불변, 공급자 오류, 악성 지시문 및 잘못된 근거를 다룬다. |
| Alembic 업그레이드 | `0003_agent → 0004_handover` 적용 후 합성 티켓, 변경 이벤트, SOP, 768차원 벡터, 기존 분석 결과 보존을 확인했다. 빈 DB에 전체 마이그레이션도 적용했다. |
| React와 Nginx | `tsc --noEmit`, Vite 빌드 통과. 브라우저에서 자동 선정, 수동 제외, AI 결과, 누락 답변, 인계조 확정, 인수조 확인을 재현했다. |
| Compose | 개발·운영 설정 문법 확인. Windows Docker Desktop에서 개발 조합을 시작하고 Nginx의 `GET /health` 200 `{"status":"ok"}`, 내부 서비스 상태와 DB 포트 비공개를 확인했다. |

### 실제 Gemini 스모크

가상 티켓 한 건을 사용했다. 같은 입력으로 실행했으며 임베딩 요청은 0회였다. 토큰은 공급자가 반환한 사용량만 기록했다.

| 모델 | 모델 요청 | 성공한 도구 | 반환 토큰 | 결과 |
| --- | ---: | ---: | ---: | --- |
| `gemini-3.8-flash` 기본 설정 | 4 | 0 | 0 | 두 번 실행. 상류 HTTP 504를 확인했다. |
| `gemini-3.7-flash` 검증 전용 지정 | 6 | 5 | 2,574 | 한 실행에서 실제 도구 호출을 검증했다. 상류 503·504로 최종 구조화 응답 검증은 남아 있다. |

성공한 도구 순서는 `get_shift_tickets → get_ticket_details → get_ticket_history → get_pending_actions → identify_handover_gaps`였다. Fake 공급자에서는 같은 경로의 구조화 초안, 근거 링크, 수동 편집과 최종 확정을 검증했다. [스모크 명령](AGENT.md#4단계-인수인계-연동)

### 현재 범위

근무조와 일정을 CLI에서 등록한다. 단일 연속 운영 일정과 조직 전체 조회를 전제로 하며, 보고서 변경 권한은 조 소속에 따라 제한한다. 누락 확인 요청은 화면에서 담당자와 함께 표시한다. Gemini는 최대 24개 티켓을 검토하며, 전체 대상과 변경 이력은 스냅샷에 보존한다. 실제 Gemini의 최종 JSON 수신 검증이 남아 있다. Ubuntu용 운영 Compose는 설정 검증까지 진행했다.
