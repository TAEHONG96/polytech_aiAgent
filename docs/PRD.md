# 제품 요구사항

설계 초안 · 2026-11-18 (KST) · 구현은 검토 승인 이후 시작한다.

이 문서에서 미해결은 `open`·`in_progress`·`waiting`, 미완료 작업은 `todo`·`in_progress`·`blocked`를 뜻한다.

## 목적과 사용자

IT 운영자와 데이터센터 테크니션이 하나의 웹 화면에서 장애를 기록하고, 과거 사례와 SOP를 검토하고, 교대 시 미완료 작업을 다음 근무조에 전달한다. 시연은 가상 티켓, 가상 SOP, 가상 계정과 근무조로 진행한다. Gemini는 진단 절차와 보고서 초안을 제안한다. 상태 변경, 작업 기록, 보고서 확정은 인증된 사용자가 직접 수행한다.

| 사용자 | 할 수 있는 일 |
| --- | --- |
| 운영자·테크니션 (`operator`) | 단일 조직의 티켓·이력·SOP·보고서 조회, 티켓과 후속 작업 편집, 티켓 분석 요청, 소속 인계조의 인수인계 초안 생성·편집, 분석 근거와 도구 실행 기록 조회 |
| 교대 책임자 (`shift_lead`) | 운영자 권한과 소속 인계조의 보고서 승인. 검토자가 작성자와 같을 수 있다. |
| 배포 운영자 | UI 밖에서 계정·조 편성·근무 회차와 SOP 데이터 반입, 백업·복원, 배포와 환경설정 관리 |

## MVP 요구사항과 수용 기준

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| R1 | 티켓 생성·조회·수정·삭제, 상태·우선순위·담당자·담당 회차 표시 | 가상 티켓을 생성하고 담당자를 배정한 뒤 상태를 전환할 수 있다. 삭제는 `closed` 티켓의 보관 처리이며 기본 목록에서 제외된다. |
| R2 | 작업 이력 및 후속 작업 | 상태·담당자·필드·후속 작업 변경과 운영 메모가 시간순으로 표시되고 작성자와 시간이 남는다. 보류된 작업도 교대 시 확인할 수 있다. |
| R3 | 근거 기반 장애 분석 | 티켓 상세에서 분석을 요청하고 진단 단계, 가설, 누락 정보, 근거와 불확실성을 확인한다. 과거 해결 티켓과 개별 SOP 절을 열 수 있다. 근거 부족 또는 AI 실패 상태를 구별한다. |
| R4 | 근무조별 미해결 티켓 및 누락 정보 | 인계조 담당의 활성 티켓, 해결 상태 티켓의 미완료 작업, 현재 미배정 업무가 화면과 보고서에 표시된다. 영향 범위·다음 조치·담당자·마감 시각 등을 규칙으로 확인한다. |
| R5 | 보고서 자동 작성 및 승인 | 교대 화면에서 한 번 요청하면 초안이 생성된다. 운영자가 검토·편집하고 책임자가 승인하면 승인자·시각·내용을 보존한다. AI 실패 시 수집된 자료로 수동 작성할 수 있다. 근무 중 자료가 바뀌면 최신 초안으로 갱신할 수 있다. |
| R6 | 모의 시연과 실행 추적 | 가상 데이터로 티켓 등록부터 보고서 승인까지 재현한다. 각 실행의 도구명·순서·성공 여부·참조 ID를 확인한다. 기본 통합 테스트는 API 키 없이 실행한다. |

### 티켓과 교대 업무 규칙

- 상태는 `open`, `in_progress`, `waiting`, `resolved`, `closed`다. 새 티켓은 `open`으로 시작한다. 우선순위는 `P1`부터 `P4`까지이며 P1이 가장 높다. 티켓 수정 권한과 상태 전이 조건은 [API 계약](API.md#티켓-상태-전이)을 따른다.
- 티켓은 사용자 한 명과 담당 근무 회차 한 개를 가질 수 있다. 개인을 배정하려면 해당 회차의 근무조 소속이어야 한다. 미배정은 허용하고 교대 요약에 표시한다. 시연은 단일 운영 조직과 하나의 연속적인 교대 일정으로 가정한다.
- 인계조는 업무를 전달하는 근무조, 인수조는 직후 회차를 담당하는 조를 뜻한다. 교대 화면에서 현재 또는 직전 회차를 선택한다. 보고서는 선택 회차에 배정된 미해결 티켓과 미완료 작업이 있는 해결 티켓, 회차 미배정 및 이전 회차 배정 상태로 남은 동일 유형의 티켓을 포함한다. 이전 회차 배정 건은 이월로 표시한다. 선택 회차 시간 범위 내 해결된 인계조 담당 및 미배정 건도 포함한다. 종료 티켓은 미완료 작업을 둘 수 없다.
- 필수 규칙 검사는 활성 티켓의 영향 설명·담당 회차·담당자·다음 조치 누락, 대기 티켓의 재확인 시각 누락, 활성 후속 작업의 담당자·마감 누락 및 기한 초과를 표시한다. AI는 확인 질문을 추가할 수 있다. 사용자는 누락 항목을 확인한 뒤 남은 이유를 기록해 승인할 수 있다.
- 초안 생성은 사용자의 요청으로 시작한다. 현재·직전 회차의 초안을 생성·편집·갱신·승인할 수 있다. 승인 시 자료를 다시 검증하며 티켓 담당 회차나 사용자 배정은 기존 티켓 화면에서 변경한다. 이전 초안과 승인된 보고서는 조회용으로 보존한다.

### 시연과 품질 목표

가상 스토리지 응답 지연을 등록하고 과거 해결 사례와 SOP를 확인한다. 작업 일부를 미완료로 남긴 채 담당자·재확인 시각 누락을 드러낸다. 교대 초안에서 근거와 도구 실행 이력을 검토하고, 보완 후 책임자가 결과를 확정한다. 같은 데이터로 Gemini 실패와 근거 없는 검색을 재현한다.

- 초기 규모 가정은 동시 사용자 5명, 티켓 1,000건 이하, 검색 청크 10,000개 이하이다. 배포 후보 서버의 사양과 측정 방법은 [개발 계획](TASKS.md)에 기록한다.
- 배포 후보에서 비AI 주요 읽기 API p95 500ms 이하를 잠정 목표로 한다. 모델 실행에는 전체 시간 예산을 적용하고 폴링으로 상태를 보여 준다.
- 기본 화면 언어와 표시 시간대는 한국어와 `Asia/Seoul`이다. API는 오프셋을 포함한 시간을 받고 UTC로 반환한다. 제목·상태·오류 등의 핵심 정보는 키보드로 확인할 수 있고 상태는 문자로도 표시한다.
- MVP 후속 범위는 SSO, 조직별 데이터 격리, 예약 발송과 알림, 첨부파일·임의 문서 업로드, SLA 자동화, 외부 ITSM 동기화다. 실제 인프라 변경은 제품 범위 밖이다.
