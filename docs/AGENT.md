# Gemini 에이전트 설계

설계 초안 · 2026-11-18 (KST)

## 역할과 호출 계약

장애 분석은 티켓 증상, 해결 사례와 SOP에서 진단 단계와 확인 질문을 제안한다. 인수인계는 서버가 수집한 회차·티켓·작업·누락 정보 스냅샷을 읽고 보고서 초안을 제안한다. 모의 환경에서도 도구는 업무 데이터 조회만 제공한다. 티켓 갱신, 보고서 승인과 운영 절차 실행은 사람의 별도 업무 명령으로 처리한다.

| 설정 | 설계 |
| --- | --- |
| Provider | `AGENT_PROVIDER=fake\|gemini`. Fake는 고정된 도구 호출, 재현 가능한 검색용 임베딩과 결과·실패 응답을 만든다. 실제와 동일한 작업·도구·검증 경로를 통과한다. |
| 생성 모델 | `GEMINI_GENERATION_MODEL=gemini-3.8-flash` 후보. worker의 Google Gen AI Python SDK를 통한 `generate_content`를 사용한다. 대상 계정에서 가용성, 함수 호출 왕복, 구조화 출력 및 응답 시간을 확인한 뒤 확정한다. [Gemini 3.8 Flash 모델](https://aistudio.google.com/docs/models/gemini-3.8-flash) · [모델 사용 종료 일정](https://aistudio.google.com/docs/deprecations) · [Python SDK](https://github.com/googleapis/python-genai) |
| 임베딩 모델 | `GEMINI_EMBEDDING_MODEL=gemini-embedding-2`, 출력 768차원 후보. 문서와 질의 텍스트에 공식 검색용 접두 체계를 적용한다. 모델명·차원·입력 형식·분할 버전·provider를 프로필에 포함한다. [Gemini 임베딩](https://aistudio.google.com/docs/embeddings) |
| 키와 전송 내용 | `GEMINI_API_KEY`는 worker 환경변수에서 읽는다. 모델에 보내는 데이터는 사용 권한이 있는 합성 티켓과 SOP의 필요한 필드로 제한한다. 실제 데이터 반입 전에는 전송 항목·서비스/계정 조건·조직 정책을 검토한다. [Gemini API 이용 조건](https://aistudio.google.com/docs/terms) |

## 도구 허용 목록

모든 도구는 worker의 조회 핸들러로 구현한다. 대상 ID, 사용자·회차, 대상 버전과 권한은 서버 실행 컨텍스트에서 결정한다. 도구 입력에 있는 추가 필드·미등록 이름·잘못된 타입은 거부하고 추적한다. 입력 원문, SQL, 셸, URL 실행, 외부 ITSM, 서버 제어, 쓰기 도구는 에이전트에 노출하지 않는다.

| 도구 | 허용 실행 | 모델 인자 | 결과 |
| --- | --- | --- | --- |
| `get_ticket_context` | 장애 분석 | 없음 | 입력 티켓의 생성 시점 스냅샷, 제한된 관련 작업과 이력, 규칙 기반 누락 ID |
| `search_similar_incidents` | 장애 분석 | `query` 최대 300자, `limit` 1–5 | 대상 티켓을 제외한 유사 해결 사례의 제한된 발췌, ID·리비전·거리 기반 점수 |
| `search_sop` | 장애 분석 | `query` 최대 300자, `limit` 1–5 | 현재 발행 SOP 절, 버전 ID, 제한된 발췌, 점수 |
| `get_handoff_snapshot` | 인수인계 | 없음 | 지정 보고서 리비전의 인계·인수 회차, 미해결·미완료·이월·해당 회차의 해결 요약, 서버 누락 항목 및 근거 키 |

## 실행 순서

1. API가 인증, 입력 버전, 멱등 키를 확인한다. 티켓 분석은 입력 스냅샷을 저장한다. 보고서 생성·갱신은 인수인계 서비스가 스냅샷과 기본 본문, AI 실행을 같은 트랜잭션에 기록한다.
2. worker가 실행 리스를 얻고 요청 계정 활성 상태와 대상 권한을 재확인한다. 미리 정한 조회로 대상 스냅샷을 준비한다. 티켓·SOP 원문은 참고 데이터 필드로 전달하며 문서 내부 지시문에 실행 권한을 부여하지 않는다.
3. Gemini에 용도별 함수 선언을 제공한다. SDK 자동 실행을 끄고 모델의 함수 호출을 검증 후 직접 실행한다. 원본 모델 응답의 parts와 thought signature를 메모리에서 보존해 도구 응답과 이어 붙인다. 병렬 제안은 호출과 응답을 순서 및 API가 제공한 호출 ID에 맞춰 연결한다. 응답 본문과 서명은 감사 로그에 저장하지 않는다. 수집 라운드 최대 3회, 전체 도구 호출 8회, 동일 이름·인자 호출은 캐시 응답을 사용하고 호출 한도에 포함한다. [Function Calling](https://aistudio.google.com/docs/function-calling) · [Python SDK의 수동 함수 호출](https://github.com/googleapis/python-genai)
4. 장애 분석은 사례·SOP 조회를 각각 한 번 이상 시도한다. 모델이 생략하면 서버가 스냅샷 제목·증상으로 기본 질의를 수행한다. 인수인계는 스냅샷 도구가 한 번 호출되도록 보장한다. 서버 보완 호출도 동일한 도구 이력에 시작 주체와 함께 기록한다. 필수 조회를 위한 호출 한도를 우선 확보한다.
5. 모은 근거 키와 데이터로 도구가 비활성화된 별도 구조화 출력 호출을 보낸다. 서버가 Pydantic 경계에서 타입·크기·허용 근거 키를 검사한다. 근거 키는 도구가 해당 실행에서 돌려준 것만 허용한다. 인수인계 티켓·작업 ID는 스냅샷에 포함된 것만 허용한다. 타입 또는 참조 오류는 시간 예산 안에서 한 번 수정 요청하고 다시 실패하면 종료한다. [Gemini 구조화 출력](https://aistudio.google.com/docs/structured-output)
6. worker가 리스 소유를 검증하고 실행 상태·결과·인용을 커밋한다. 인수인계 서비스는 초안 상태와 입력 리비전 일치 시에만 본문을 새 리비전으로 적용한다. 늦은 분석 결과는 원래 입력 버전에 연결하고 화면에서 최신 티켓과 달라졌음을 표시한다.
7. 운영자가 교대 초안의 내용을 수정하거나 확인 사유를 기록한다. 책임자가 승인하면 서버가 현재 자료와 비교한다. 승인 시점에 변경된 자료가 있으면 편집 내용을 보존하고 명시적 갱신을 요청한다.

## 검색과 근거

- 과거 티켓은 해결 요약이 있는 비보관 `resolved`·`closed`를 사용한다. 제목·서비스·증상·영향·해결을 정해진 순서로 변환한다. SOP는 발행 문서의 제목과 절을 단위로 사용한다. 색인 초깃값은 청크당 약 400 토큰과 60 토큰 중첩이며 절의 식별자를 보존한다.
- 소스는 변경 트랜잭션에서 색인 작업과 함께 등록한다. worker가 차원·유한값·영벡터 여부를 확인하고 전체 청크를 원자적으로 공개한다. 티켓이 재개·보관되거나 SOP의 새 버전이 발행되면 구버전을 즉시 검색에서 제외한다. 색인 작업을 실행할 때 현재 리비전을 확인하고 이미 대체된 작업의 게시를 막는다.
- 두 소스를 각각 필터한 뒤 코사인 거리로 정렬한다. 점수는 `1 - 거리`로 표시하고 정확한 동률은 청크 ID로 정렬한다. 소스마다 중복을 줄여 최대 5건씩 전달한다. 점수 하한은 시연용 사례·무관 질의로 보정하고 합격 기준을 기록한다. 점수는 가설의 사실 여부를 나타내는 확률로 사용하지 않는다.
- 근거 응답에는 서버 생성 키, 소스 유형, 제목, 발췌, 버전과 티켓 번호 또는 SOP 절 링크가 들어간다. 답변 항목별 근거 목록이 비면 `basis_status=insufficient`와 이유·확인 방법을 요구한다. 결과가 없는 검색, 색인 대기, 임베딩 요청 실패는 별도 결과 코드로 기록한다.
- 인수인계의 스냅샷 티켓·작업 목록과 누락 결과는 서버가 렌더링한다. 모델의 요약이나 편집 본문이 이 원본 목록을 대체하지 않는다. 모델에 넘기는 티켓·작업 요약 및 발췌를 크기 한도로 제한하고 생략 건수를 경고로 표시한다. 전체 스냅샷은 UI에서 확인할 수 있다. 과거 이력·문서가 변경되어도 저장한 근거 발췌와 출처 버전을 보여준다.

## 결과 스키마와 사용자 상태

| 결과 | 필드 |
| --- | --- |
| 공통 | `schema_version`, `summary`, `warnings[]`. 근거가 있는 각 제안에 `citation_keys[]`, `basis_status` (`supported`, `insufficient`), 불확실성 설명을 둔다. |
| 장애 분석 | `hypotheses[]`(가설·추정 수준·근거), `diagnostic_steps[]`(순서·확인 대상·관찰할 결과·근거), `missing_information[]`(필드/질문/확인 방법). 추정 수준은 `low\|medium\|high`이며 확정 여부를 대신하지 않는다. |
| 인수인계 | `summary`, `follow_ups[]`(선택 티켓/작업 ID·확인 사항·근거), `unverified_items[]`(미확인 사유·확인 방법·관련 근거). 담당자·마감·누락 규칙 값은 서버 스냅샷에서 표시한다. |

| 상황 | 처리 |
| --- | --- |
| 키 누락·잘못된 설정·모델 접근 거부 | `AI_CONFIGURATION`으로 종료. 설정 변경 후 사용자가 재실행할 수 있다. |
| 429·일시 5xx·연결 오류 | 호출 전체 예산 안에서 지수 백오프와 지터로 최대 한 번 재시도한다. 서버가 보낸 재시도 시간이 예산을 넘으면 즉시 종료한다. `AI_RATE_LIMIT` 또는 `AI_UNAVAILABLE`과 재실행 가능 여부를 표시한다. |
| 시간 초과·출력 차단·검증 실패 | `AI_TIMEOUT`, `AI_CONTENT_BLOCKED`, `AI_INVALID_OUTPUT`으로 구분한다. 쓸 수 있는 티켓·스냅샷과 수동 업무 화면을 유지한다. |
| 자료 없음 또는 임베딩만 일시 실패 | 상태를 `NO_MATCHES`, `INDEX_PENDING`, `RETRIEVAL_UNAVAILABLE`로 구별해 경고를 기록한다. 검증 가능한 자료만 답변에 사용하며 근거가 없는 제안은 확인 필요로 표시한다. |
| 프로세스 중단·리스 만료 | 일시 장애로 인해 작업이 중단된 경우 두 번째 시도까지만 허용한다. 이전 소유자의 늦은 결과는 저장 또는 반영하지 않는다. |

실행 초깃값은 큐 접수부터 전체 120초, 실행 시도당 60초 및 개별 네트워크 요청당 최대 15초다. 재시도도 전체 예산에 포함된다. worker가 상태를 점검할 때 예산이 지난 행을 종료하며, worker가 중단된 동안에는 UI가 대기 지연을 표시한다. 내역은 실행 ID·시도·순서·도구명·상태·실행 시간·마스킹 인자 요약과 근거 ID를 남긴다. [Gemini 오류 처리](https://aistudio.google.com/docs/troubleshooting)
