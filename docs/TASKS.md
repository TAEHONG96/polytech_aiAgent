## 합성 데이터와 검증 운영

- 데이터는 같은 결과가 나오도록 고정된 식별자와 텍스트를 사용한다. 최근 시점 기반 교대 회차는 공통 기준 시각을 주입하고 테스트에서는 고정한다. 시드 반복 실행이 사용자가 편집한 티켓을 덮지 않도록 삽입 키와 자연키를 정한다.
- 최소 시연 세트에는 2개 근무조, 현재·직전·다음 교대 회차, 운영자와 서로 다른 조의 책임자, 유사 장애와 무관 장애, 문서 구버전, 미배정 티켓, 기한 초과 및 근거가 부족한 티켓가 들어간다.
- Python 단위 테스트는 전이·누락·스키마 검증에 사용한다. API와 SQL 제약은 Compose의 별도 PostgreSQL 테스트 DB에서 검증한다. 브라우저 시연은 동일 출처 Nginx 경로로 진행한다. Gemini 없는 테스트가 기본이며, 실제 키를 쓰는 스모크는 명시적으로 구분한다.
- 색인 품질 측정은 기대 SOP/티켓이 상위 5건에 드는 비율과 무관한 질의에서 근거 부족이 표시되는 비율을 기록한다. 테스트 묶음에는 약어, 한국어 표현 차이, 근거가 없는 장애를 포함한다. 기준 쿼리와 임계값 조정용 쿼리를 구분한다.
- 변경 단계별 증적에는 테스트 명령, 입력 환경·이미지·모델 버전, 통과/실패 결과, 남은 제약을 기록한다. 복원은 새 DB 볼륨에서 티켓 이력·승인 보고서·벡터 검색까지 비교한다.
